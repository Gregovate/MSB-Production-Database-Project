# Introduction

Every new contributor encounters questions during their first few editing sessions.

That is normal.

This guide describes the most common problems and how to solve them.

If you do not find your answer here, contact the MSB project administrator before trying to guess.

It is always better to ask than to accidentally damage a document.

---

# Problem: I Cannot Open the MSB Project

## Possible Causes

* The project has not been downloaded.
* The project folder was moved.
* You are opening the wrong folder.

## Solution

1. Open Visual Studio Code.
2. Select **File → Open Folder**.
3. Browse to your local MSB project folder.
4. Click **Select Folder**.

If you cannot find the project folder, see:

[03 — Get the MSB Documentation on Your Computer](03_Get_MSB_Documentation_on_Your_Computer.md)

---

# Problem: GitHub Says I Do Not Have Access

## Possible Causes

* You are signed into the wrong GitHub account.
* Your GitHub invitation has not been accepted.
* Access has not yet been granted.

## Solution

Verify that you are signed into the correct GitHub account.

If you still cannot access the project, contact the MSB project administrator.

Do **not** create your own copy of the project.

---

# Problem: My Document Looks Strange

## Possible Causes

* Missing blank lines.
* Missing Markdown symbols.
* A heading was accidentally changed.
* A list is incorrectly formatted.

## Solution

1. Open the Markdown Preview.
2. Compare the document with nearby sections.
3. Correct the formatting.
4. Save the document.
5. Check the Preview again.

---

# Problem: The Preview Does Not Match What I Expected

## Possible Causes

* Missing Markdown formatting.
* An image or link is incorrect.
* The document has not been saved.

## Solution

Save the document using:

`Ctrl + S`

Refresh the Preview if necessary.

Review the surrounding Markdown for missing symbols or blank lines.

---

# Problem: I Edited the Wrong Document

This happens occasionally.

Do not panic.

If the changes have **not** been submitted:

* Close the document.
* Discard the unwanted changes if appropriate.
* Open the correct document.

If you are unsure how to discard changes safely, ask the project administrator.

---

# Problem: I Forgot to Save My Work

Look at the document tab.

If you see a white dot, the document contains unsaved changes.

Save the document using:

`Ctrl + S`

Develop the habit of saving frequently while you work.

---

# Problem: My Changes Do Not Appear in Source Control

## Possible Causes

* The document was not saved.
* You edited a copy outside the project folder.
* The wrong project is open.

## Solution

1. Save the document.
2. Verify you are editing the file inside the MSB project.
3. Return to Source Control.

If the document still does not appear, ask for assistance before continuing.

---

# Problem: I Cannot Find the Document I Need

Use the file search feature.

Press:

`Ctrl + P`

Begin typing part of the filename.

VS Code will display matching documents.

---

# Problem: I Cannot Find Specific Information

Search all project documents.

Press:

`Ctrl + Shift + F`

Enter the word or phrase you are looking for.

VS Code will search every document in the project.

---

# Problem: I Accidentally Deleted Something

If you notice the mistake before submitting your work:

* Do not panic.
* Restore the deleted text if possible.
* Compare your work with the original using Source Control.

If you are unsure how to restore the document, ask for assistance.

Remember, the official documentation has **not** been changed yet.

---

# Problem: Someone Else Changed the Same Document

If VS Code reports a conflict:

Stop.

Do not begin deleting text or copying information between documents.

Contact the project administrator for assistance.

Conflicts are much easier to resolve when handled carefully.

---

# Problem: My Pull Request Received Review Comments

This is completely normal.

Open the review comments.

Read every comment carefully.

Update your document.

Commit the corrections.

Push the updated changes.

Do **not** create a second Pull Request for the same work.

See:

[10 — Respond to Review Comments](10_Respond_to_Review_Comments.md)

---

# Problem: I Am Not Sure Whether Something Should Be Changed

If you are uncertain:

Stop.

Ask.

Documentation often affects many other procedures.

A quick question can prevent unnecessary work later.

---

# Problem: I Made Several Different Types of Changes

Whenever practical:

Keep one Pull Request focused on one topic.

Good examples:

* Correct spelling.
* Update screenshots.
* Clarify one procedure.

Avoid combining unrelated changes into one large submission.

Small changes are easier to review.

---

# Problem: A Link Does Not Work

Check that:

* The filename is spelled correctly.
* Uppercase and lowercase letters match.
* The document actually exists.
* The file extension is correct.

Preview the document and test the link before submitting your work.

---

# Problem: An Image Does Not Appear

Verify that:

* The image exists.
* The filename is correct.
* The image is stored in the correct **Images** folder.
* The Markdown image link matches the filename exactly.

---

# Problem: VS Code Looks Different From This Guide

Visual Studio Code is updated regularly.

Buttons and menus occasionally move.

If a screen looks different:

Read the labels carefully.

Often the feature is still available with a slightly different appearance.

If you cannot find the feature, ask the project administrator.

---

# Problem: I Forgot Some Markdown

That is expected.

Very few contributors memorize Markdown.

Open:

[11 — Markdown Quick Reference](11_Markdown_Quick_Reference.md)

Use it whenever needed.

---

# Best Practices

Following these simple habits will prevent most problems.

Before editing:

* Update your project.
* Open the correct document.
* Read the surrounding text.

While editing:

* Save often.
* Use the Preview.
* Keep formatting consistent.

Before submitting:

* Review your changes.
* Check spelling.
* Test links.
* Verify images.
* Make sure only the intended files changed.

---

# When to Ask for Help

Please ask for assistance if:

* GitHub reports an error you do not understand.
* You cannot access the project.
* You encounter a merge conflict.
* You are unsure which document should be edited.
* You believe documentation is incorrect.
* You think a procedure should be reorganized.
* You accidentally removed a large section of text.

Questions are encouraged.

The goal is to improve the documentation while keeping the project accurate and consistent.
