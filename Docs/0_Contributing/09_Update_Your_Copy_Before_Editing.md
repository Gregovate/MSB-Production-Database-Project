# 09 — Update Your Copy Before Editing

## Before You Begin

This lesson should be completed **every time you begin working on the MSB documentation.**

Unlike the installation steps, this is part of your normal workflow.

Before starting, you should already have:

* Visual Studio Code installed.
* Git installed.
* The MSB project on your computer.
* Permission to access the MSB GitHub project.

---

# Why Do I Need to Update?

Other contributors may have changed the documentation since the last time you worked on it.

Updating your copy ensures that:

* You are reading the newest documentation.
* You are editing the latest version.
* You avoid accidentally overwriting someone else's work.
* Your changes will be easier to review.

**Always update your copy before beginning a new editing session.**

---

# Think of It Like This

Imagine two people editing the same Microsoft Word document.

One person updates the document on Monday.

You begin editing your older copy on Wednesday.

Now there are two different versions of the same document.

Updating your project first prevents this problem.

---

# Step 1 — Open Visual Studio Code

Start Visual Studio Code.

If the MSB project does not automatically open:

1. Choose **File**
2. Select **Open Folder**
3. Browse to your MSB project folder.
4. Click **Select Folder**.

Wait for the project to finish loading.

---

# Step 2 — Open Source Control

Click the **Source Control** icon on the left side of the VS Code window.

It normally appears as three connected circles.

If Source Control shows files that you edited previously but never submitted, stop and decide what to do before continuing.

You should normally begin a new editing session with no unfinished work.

---

# Step 3 — Synchronize with GitHub

Look for a button similar to:

* **Sync Changes**
* **Pull**
* **Fetch**
* **Synchronize**

The wording may vary depending on your version of Visual Studio Code.

If you are unsure which button to use, ask the project administrator.

For normal documentation work, the goal is simply to update your local copy with any approved changes from GitHub.

---

# What Happens During an Update?

VS Code contacts GitHub and checks whether newer documentation is available.

If changes are found:

* The new documents are downloaded.
* Your project is updated.
* Your documentation now matches the official project.

If no changes are available, VS Code simply reports that everything is already up to date.

---

# If There Are No Updates

Sometimes you will already have the latest version.

That is perfectly normal.

No additional action is required.

You are ready to begin editing.

---

# If New Documents Are Downloaded

After updating:

Take a few moments to review any documents you plan to edit.

Someone else may have already updated part of the procedure.

Reading the newest version before making changes helps avoid duplicate work.

---

# Updating Does Not Remove Your Work

Many new users worry that updating will erase their documents.

Normally, if you have already completed your previous work and your project is in a clean state, updating simply downloads newer approved changes.

Your previously approved work remains part of the project.

---

# If VS Code Reports a Conflict

Occasionally VS Code may report a conflict.

This usually means:

* Someone else changed the same document.
* You also changed that document.

Do **not** guess how to resolve the conflict.

If this happens:

* Save any work.
* Do not delete anything.
* Contact the project administrator for assistance.

Conflicts are uncommon when contributors update before beginning their work.

---

# A Good Daily Routine

Each time you work on the documentation:

1. Open VS Code.
2. Open the MSB project.
3. Update your project.
4. Open the document you want to edit.
5. Make your changes.
6. Save your work.
7. Review your changes.
8. Submit your Pull Request.

Following the same routine every time greatly reduces mistakes.

---

# Working on More Than One Computer

Some contributors work from more than one computer.

For example:

* Office computer
* Home computer
* Laptop

If you do this:

Always update the project after opening it on each computer.

This ensures every computer is using the newest documentation.

---

# If You Have Been Away for a While

If it has been several weeks since you last worked on the project:

Update the project before opening any documents.

There may have been many approved changes since your last editing session.

Starting with the latest version will save time later.

---

# Before Making Your First Edit

After updating, ask yourself:

* Am I working from the newest version?
* Is this the correct document?
* Has someone already made the change I planned to make?

If the answer to all three questions is yes, you are ready to begin editing.

---

# Common Beginner Mistakes

## Editing Before Updating

Always update first.

---

## Working from an Old Copy

Never keep separate copies of the documentation outside your MSB project folder.

Always use the project that was cloned from GitHub.

---

## Ignoring Update Messages

If VS Code reports that updates are available, install them before beginning new work.

---

## Skipping the Daily Update

It only takes a few seconds.

Making it part of your routine prevents many problems later.

---

# What You Have Learned

You now know how to:

* Update your local copy of the MSB documentation.
* Keep your project synchronized with GitHub.
* Avoid editing outdated documents.
* Recognize when something needs attention before you begin working.

Updating before every editing session is one of the simplest habits you can develop, and it greatly reduces the chance of conflicts with other contributors.
