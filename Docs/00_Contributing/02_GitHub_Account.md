# 02 — Create a GitHub Account and Get Access

Visual Studio Code and Git should already be installed before starting this section.

If they are not installed, complete:

**01_Install_VSCode_and_Git.md**

---

# What Is GitHub?

GitHub is the online service where the controlled MSB documentation is stored.

You can think of it somewhat like a shared Google Drive folder, but GitHub is designed to keep a detailed history of files and changes.

GitHub allows us to:

* Store the official documentation.
* Control who has access.
* Keep a history of changes.
* Review proposed changes.
* Approve a change before it becomes official.

---

# GitHub and Git Are Different

The names are similar, which can be confusing at first.

## Git

Git is software installed on your computer.

It tracks file changes.

## GitHub

GitHub is an online service.

It stores the shared MSB copy and manages access and reviews.

You will use both, but VS Code will handle much of the interaction for you.

---

# Part 1 — Check Whether You Already Have a GitHub Account

Open your web browser.

Go to:

**https://github.com/**

If you already have a GitHub account that you are comfortable using for MSB documentation, you do not need to create another one.

Sign in and continue to the section:

**Getting Access to the MSB Repository**

If you do not have a GitHub account, continue below.

---

# Part 2 — Create a GitHub Account

At the GitHub website, choose:

**Sign up**

GitHub will ask you for information including an email address and password.

Use an email address that you regularly check.

You will need access to that email account to complete the registration process and receive future GitHub notifications.

---

# Choose a Username

GitHub will ask you to choose a username.

Your username is the name other contributors may see next to changes you submit.

Choose something appropriate for working with the MSB organization.

You do not need to create a technical or programming-style username.

---

# Create a Secure Password

Choose a password following GitHub's current password requirements.

Do not share your GitHub password with another person.

MSB administrators do not need your password to give you documentation access.

---

# Verify Your Email Address

GitHub may send a verification message to the email address you provided.

Open your email.

Look for the GitHub verification message.

Follow the instructions in the message.

If you do not see the email:

1. Wait a few minutes.
2. Check your Spam or Junk folder.
3. Verify that you entered the correct email address.

---

# Part 3 — Sign In to GitHub

After creating and verifying the account:

1. Go to:

   **https://github.com/**

2. Choose **Sign in**.

3. Enter your GitHub account information.

### Expected Result

You can successfully sign in to GitHub and see your GitHub home page.

---

# Part 4 — Send Your GitHub Username to the MSB Administrator

Creating a GitHub account does **not** automatically give you access to MSB documentation.

The MSB documentation is controlled.

An administrator must give your GitHub account permission to access the appropriate project.

Send your **GitHub username** to the MSB administrator.

Do not send your password.

The administrator only needs your GitHub username.

---

# Part 5 — Watch for the Invitation

After access has been assigned, you may receive an invitation from GitHub.

The invitation may appear:

* In your email.
* In GitHub notifications.
* On GitHub after you sign in.

Open the invitation and review it.

Make sure the invitation is for the expected MSB project or organization.

Accept the invitation.

---

# Part 6 — Verify That You Have Access

After accepting the invitation, use the project link provided by the MSB administrator.

You should be able to open the MSB project in your web browser.

You will probably see:

* The project name near the top.
* A list of files and folders.
* Documentation about the project.

Do not worry about all of the buttons and controls on the GitHub page.

You will do most of your documentation work in VS Code, not directly on this web page.

### Expected Result

You can sign into GitHub and open the MSB project you were given permission to use.

---

# Important — Access Does Not Mean Automatic Approval

Being given access does not mean that changes you make immediately become official MSB documentation.

The workflow is intentionally designed so changes can be reviewed.

The normal process is:

**You prepare a change**

↓

**You submit the change for review**

↓

**The change is reviewed**

↓

**Corrections can be requested**

↓

**An approved change is added to the official documentation**

This protects both you and the documentation.

You can propose improvements without worrying that an unfinished edit will immediately replace the official procedure.

GitHub can display and sometimes edit files directly in your web browser.

For this training, **do not begin editing the documentation from the GitHub website**.

We want your normal workflow to use the MSB copy on your computer through VS Code.

That process provides better editing, preview, and review tools.
